# Smart Resource Hub — Batch C7

A responsive project website for **Student Innovation – Ideas Focused on the Intelligent Use of Resources for Transforming**. The website includes the demo login, resource categories, illustrative dashboard, project methodology, a detailed execution plan, the ten system-design layers, technology options, student idea submission, and expected outcomes.

## Files
- `index.html` — page structure and project content
- `style.css` — responsive styling, abstract motion background, cards, and animations
- `script.js` — demo login, show/hide password, navigation, idea form, and scroll reveals

## Run locally (Windows)
1. Extract the ZIP file.
2. Open the `resource_smart_campus_web` folder in Visual Studio Code.
3. Open `index.html` in a browser, or use the Live Server extension.
4. Demo login:
   - Email: `student@campus.com`
   - Password: `campus123`

## Project content included
1. **Resource categories:** energy/electricity, water, waste, materials, and campus facilities.
2. **Methodology:** problem identification, idea generation, resource analysis, technology selection, solution development, testing/evaluation, and implementation/feedback.
3. **Execution plan:** actions and expected output for each methodology phase.
4. **System design layers:** input, resource data, processing, analysis, innovation/solution, decision-making, monitoring, alert, user, and feedback.
5. **Technology options:** IoT, AI, sensors, mobile apps, and a web interface.
6. **Goals/outcomes:** intelligent and sustainable resource utilization, reduced wastage, better efficiency, cost awareness, student-driven solutions, monitoring, and continuous improvement.

These sections are based on the project material supplied in the conversation. Specific sensor configurations, algorithms, measured campus figures, and deployment details were not specified in that material; the site therefore presents technologies as options and dashboard figures as examples.

## Important notes
The login is a front-end demo only. The credentials are visible in JavaScript and can be bypassed. Do not use real passwords. Production use requires server-side authentication, password hashing, secure sessions, HTTPS, and a database. Idea submissions are only kept in browser memory and are not sent to a server. Dashboard figures are illustrative and should be replaced with verified campus data.

The motion-led visual treatment is an original abstract design; it does not use Lando Norris's photo or copy another site's assets.
